# Ghost in the Shell — как источник архитектурных идей (НЕ шаблон реализации)

> **Оговорка (ключевая):** GiTS стоит использовать как *источник архитектурных идей*, а не как
> шаблон для реализации. Аналогии полезны ровно настолько, насколько они помогают мыслить
> инженерно — но система строится вокруг инженерных принципов (LAW K1–K8, ADR-001..077), а не
> вокруг художественного мира. Puppet Master НЕ является целью проекта: мы строим модульную
> платформу, а не "искусственный разум".

## Соответствия GiTS → KROFT_OS (расширенная таблица)

| Ghost in the Shell | KROFT_OS |
|---|---|
| Ghost (личность) | Долговременная память + профиль агента |
| Shell (оболочка) | Runtime + адаптеры к моделям (OmniRoute/LLM) |
| Cyberbrain | Граф знаний (Knowledge Graph 2.0) + RAG + индекс памяти |
| Section 9 | Оркестратор специализированных агентов (`ReferenceOrchestrator`, ORCH-01) |
| Tachikoma | Автономные сервисные агенты на узлах (FED-EXEC-01 listener/server) |
| Net | Общая шина сообщений (Message Bus / `INetworkTransport`, NW-01) |
| Cyberization | Подключение новых инструментов и плагинов (PLUGIN-01) |
| Puppet Master | Возникновение НОВОГО ПОВЕДЕНИЯ из накопленных знаний (не "разум", а новые возможности системы) |

## Пять слоёв, особенно ценных для KROFT_OS

### 1. Identity Layer
Каждый агент — постоянный участник системы, не просто вызов LLM. Минимальный контракт идентичности:
- уникальный ID;
- собственная память;
- специализация (`specialization`);
- уровень доверия (текущий LATEST, `ITrustRegistry.current_trust`);
- разрешения (`required_permission`);
- история действий (`IActionLog`).

→ Уже реализовано в KROFT_OS: `IIdentityRegistry` / `ITrustRegistry` (IDT-01) + `IActionLog`.

### 2. Memory Layer
Память — НЕ одна большая база, а уровни (ближе к когнитивным системам):
- краткосрочная (контекст задачи);
- рабочая (текущая сессия);
- долговременная (Vault);
- семантическая (Graph / Knowledge Graph 2.0);
- процедурная (как выполнять задачи → `Procedure` / Skill).

→ Уже реализовано в KROFT_OS: SKILL-01 (Memory Layer: working/episodic/semantic/normative+
  procedural) + SKILL-EVOLVE-01 (процедурная память эволюционирует, ADR-077).

### 3. Network Layer (наиболее актуально)
Для KROFT_OS это критично — обсуждалась возможность нескольких пользователей/узлов. Вместо
передачи всего Vault обмениваемся *избирательно*:
- знаниями;
- навыками (Skills);
- специализированными агентами;
- проверенными стратегиями.

Получается НЕ единый общий мозг, а сеть независимых узлов (federated, не centralized).

→ Уже реализовано в KROFT_OS: GitS Network Layer (FED-ORCH-01 client + FED-EXEC-01 server,
  ADR-075/076). Узел = client+server через `build_federated_node`; обмен goal→real-outcome.
  Мульти-пользователь = естественное следствие federation (каждый пользователь = узел сети).

### 4. Trust Layer
Главная проблема GiTS: нельзя безоговорочно доверять информации. Для инженерной системы:
- происхождение знания (**provenance**);
- цифровая подпись;
- рейтинг доверия (`current_trust` LATEST, не MAX);
- версия;
- автор (`author_id`);
- возможность отката (rollback / invalidation).

Особенно важно, если несколько KROFT_OS будут обмениваться знаниями (cross-node VO уже несут
`CausalMark` + `author_id` — урок Флага 1 LLM-01).

→ Частично реализовано: trust-gating (IDT-01), CausalMark/author_id на cross-node VO (FED-ORCH/EXEC).
  **Долг (вне текущих волн):** подпись/provenance/rollback на уровне Knowledge Graph-узлов и
  обмена навыками между узлами — кандидат в будущий ТЗ (Trust Layer для federation-of-knowledge).

### 5. Evolution Layer (самая интересная идея)
Эволюция происходит БЕЗ изменения самой LLM — развивается архитектура *вокруг* неё:

```
Опыт
  ↓
Анализ
  ↓
Новая стратегия
  ↓
Тестирование
  ↓
Если лучше → обновление Skill
```

→ Уже реализовано в KROFT_OS (замыкает идею): SKILL-EVOLVE-01 (ADR-077) — исход dispatch
  кормит `record_skill_outcome` (confidence success+/failure-); устойчивый провал → invalidate →
  возврат к обычному routing; recall гейтится по confidence. Это и есть "эволюция архитектуры
  вокруг LLM", а не самой модели. Аналог Puppet-Master-идеи (новые возможности из накопленного),
  но без мистики "разума".

## Что ещё стоит изучить (источники инженерных идей)

- **Ghost in the Shell** — сознание, идентичность, сети.
- **Ghost in the Shell: Stand Alone Complex** — **НАИБОЛЕЕ БЛИЗКОЕ** к KROFT_OS: система как
  совокупность автономных компонентов (специализированные агенты, сетевое взаимодействие,
  доверие, управление, безопасность). Рекомендуется как приоритетное чтение для архитектурных
  аналогий. **Не копировать художественный мир — перекладывать инженерные идеи.**
- **The Matrix** — виртуализация, уровни реальности, взаимодействие человек↔машина.
- **Her** — долгосрочная память и развитие ИИ через взаимодействие.
- **Permutation City** — цифровое сознание и вычислительные миры.
- **Diaspora** — распределённые цифровые личности и эволюция разума.

## Статус относительно KROFT_OS
Это **design-note / вдохновляющая карта**, а НЕ ADR и НЕ ТЗ. Никаких обязательств по коду.
Покрытие идеи в текущем коде (связки для будущих ADR):
- Identity ✅ (IDT-01), Memory ✅ (SKILL-01/077), Network ✅ (FED-075/076),
  Trust △ (частично: trust-gating + CausalMark; долг: provenance/подпись/rollback для обмена
  знаниями), Evolution ✅ (SKILL-EVOLVE-01 closed-loop).
- Puppet-Master-аналог (новые возможности из знаний) — emergent-свойство через Evolution Layer,
  НЕ явная цель и НЕ отдельный модуль.
